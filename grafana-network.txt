Jasně! Tady máš kompletní „od A do Z“ masterclass, jak postavit a pochopit monitoring domácí sítě v Grafaně – od úplných základů až po profi úroveň. Všechno níže můžeš nasadit doma (Raspberry Pi / mini-PC / NAS / starší server). Píšu prakticky, se vzorovými konfiguracemi.

0) Co je Grafana a jak to celé funguje
Grafana je vizualizační a alertovací nástroj. Samotná Grafana data neshromažďuje – připojuje se k datovým zdrojům (time-series DB, logy, traces) a zobrazuje je v dashboardech.
Typická pipeline monitoringu:
    1. Sběr dat (agents/exporters)
        ◦ Prometheus node_exporter – metriky OS (CPU, RAM, disk, síť).
        ◦ SNMP – metriky z routerů/switchů/AP (OpenWrt, MikroTik, UniFi…).
        ◦ Blackbox exporter – ICMP/TCP/HTTP „pingy“ dostupnosti.
        ◦ Promtail – sběr logů do Loki.
        ◦ (Volitelně) Speedtest exporter, apcupsd_exporter (UPS), smartctl_exporter (SMART disky), aj.
    2. Ukládání dat
        ◦ Prometheus (time-series metriky),
        ◦ Loki (logy),
        ◦ (Volitelně) Tempo (traces) nebo InfluxDB (alternativa k Prometheus).
    3. Vizualizace a alerty
        ◦ Grafana – panely, proměnné, alerty (e-mail/Telegram/Slack), anotace, alert rules.

1) Volba stacku (doporučení)
Pro domácí síť doporučuji Prometheus + Loki + Grafana (snadné, lehké, skvěle zdokumentované).
    • Alternativně Telegraf + InfluxDB + Grafana – taky OK, ale komunita exporterů je slabší než u Promethea.
    • Pokud chceš „vše v jednom agentovi“, podívej se na Grafana Agent (Alloy) – umí sbírat metriky/logy a posílat je do Promethea/Loki.
V této masterclass pojedu Prometheus stack (nejpraktičtější).

2) Minimální MVP: co nasadit jako první
    • Grafana – UI, dashboardy, alerty.
    • Prometheus – metriky.
    • node_exporter – metriky z každého Linux stroje (včetně toho, kde běží Prometheus).
    • blackbox_exporter – dostupnost internetu (ping DNS, gateway, veřejné služby).
    • SNMP exporter – metriky z domácího routeru/switche/AP (pokud podporují SNMP).
    • Promtail + Loki – logy (volitelné, ale velmi užitečné).

3) Docker Compose (rychlé nasazení)
Vytvoř si složku, např. ~/homelab-monitoring/ a do ní soubory níže.
3.1 docker-compose.yml
services:
  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    ports: ["3000:3000"]
    environment:
      - GF_SECURITY_ADMIN_USER=admin
      - GF_SECURITY_ADMIN_PASSWORD=change_me
    volumes:
      - ./grafana:/var/lib/grafana
    restart: unless-stopped

  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    command:
      - --config.file=/etc/prometheus/prometheus.yml
      - --storage.tsdb.retention.time=30d
      - --web.enable-lifecycle
    ports: ["9090:9090"]
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - ./prometheus-data:/prometheus
    restart: unless-stopped

  node_exporter:
    image: prom/node-exporter:latest
    container_name: node_exporter
    network_mode: host
    pid: host
    restart: unless-stopped

  blackbox_exporter:
    image: prom/blackbox-exporter:latest
    container_name: blackbox_exporter
    ports: ["9115:9115"]
    volumes:
      - ./blackbox/blackbox.yml:/etc/blackbox_exporter/config.yml:ro
    restart: unless-stopped

  snmp_exporter:
    image: prom/snmp-exporter:latest
    container_name: snmp_exporter
    ports: ["9116:9116"]
    volumes:
      - ./snmp/snmp.yml:/etc/snmp_exporter/snmp.yml:ro
    restart: unless-stopped

  loki:
    image: grafana/loki:latest
    container_name: loki
    command: -config.file=/etc/loki/local-config.yaml
    ports: ["3100:3100"]
    volumes:
      - ./loki-config.yaml:/etc/loki/local-config.yaml:ro
      - ./loki:/loki
    restart: unless-stopped

  promtail:
    image: grafana/promtail:latest
    container_name: promtail
    volumes:
      - /var/log:/var/log:ro
      - ./promtail-config.yaml:/etc/promtail/config.yml:ro
    command: -config.file=/etc/promtail/config.yml
    restart: unless-stopped
3.2 prometheus/prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  # Prometheus sám sebe
  - job_name: prometheus
    static_configs:
      - targets: ["prometheus:9090"]

  # Node exporter (host)
  - job_name: node
    static_configs:
      - targets: ["localhost:9100"]

  # Blackbox – ping gateway, DNS, veřejný internet
  - job_name: blackbox-icmp
    metrics_path: /probe
    params:
      module: [icmp]
    static_configs:
      - targets:
          - 192.168.1.1        # tvoje gateway
          - 1.1.1.1            # Cloudflare DNS
          - 8.8.8.8            # Google DNS
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - target_label: __address__
        replacement: blackbox_exporter:9115
      - source_labels: [__param_target]
        target_label: instance

  # Blackbox – HTTP(s) kontrola (např. NAS web)
  - job_name: blackbox-http
    metrics_path: /probe
    params:
      module: [http_2xx]
    static_configs:
      - targets:
          - http://192.168.1.2  # příklad: web NASu/UI routeru
          - https://example.org
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - target_label: __address__
        replacement: blackbox_exporter:9115
      - source_labels: [__param_target]
        target_label: instance

  # SNMP – router/switch/AP (povol SNMP v zařízení)
  - job_name: snmp
    static_configs:
      - targets:
          - 192.168.1.1   # router
          - 192.168.1.3   # switch
    metrics_path: /snmp
    params:
      module: [if_mib]    # základní rozhraní/statistiky
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - target_label: __address__
        replacement: snmp_exporter:9116
      - source_labels: [__param_target]
        target_label: instance
3.3 blackbox/blackbox.yml
modules:
  icmp:
    prober: icmp
    timeout: 5s
  http_2xx:
    prober: http
    timeout: 5s
    http:
      preferred_ip_protocol: "ip4"
      valid_http_versions: ["HTTP/1.1", "HTTP/2"]
      method: GET
      no_follow_redirects: false
      fail_if_ssl: false
      fail_if_not_ssl: false
3.4 snmp/snmp.yml
Základ pro většinu zařízení: if_mib (rozhraní). Funguje na OpenWrt/MikroTik/UniFi i spoustě switchů.
modules:
  if_mib:
    walk:
      - 1.3.6.1.2.1.2       # interfaces
      - 1.3.6.1.2.1.31.1.1  # high capacity counters
    version: 2
    auth:
      community: public   # změň na vlastní komunitu!

5) Základní dashboardy (co hned vidět)
Síť & dostupnost
    • ICMP latency a packet loss na gateway/DNS (Blackbox → probe_success, probe_icmp_duration_seconds).
    • HTTP dostupnost důležitých služeb (NAS, Home Assistant, Pi-hole, veřejné služby).
    • SNMP rozhraní: rychlost (in/out), chybovost, utilizace (z if_mib).
Servery/hosty
    • CPU, Load, RAM, Disk (node_exporter).
    • Síťové rozhraní hostů (tx/rx bytes, drops).
Logy (Loki)
    • Filtr chyb pro služby (např. |= "error"), časové řady výskytů, top „promluvy“.

6) PromQL – praktické dotazy
Ping success rate (posledních 5m, průměr):
avg_over_time(probe_success[5m])
ICMP latency (p95 za 10m):
histogram_quantile(0.95, sum(rate(probe_icmp_duration_seconds_bucket[10m])) by (le, instance))
Propustnost rozhraní (bits/s) – SNMP ifHCInOctets/OutOctets:
rate(ifHCInOctets[5m]) * 8
rate(ifHCOutOctets[5m]) * 8
Využití linky v % (pokud znáš rychlost portu, např. 1 Gbit/s):
( rate(ifHCOutOctets[5m]) * 8 ) / 1e9 * 100
Drops/chyby na rozhraní:
increase(ifInErrors[5m]) or increase(ifOutErrors[5m])

7) Loki – praktické dotazy (LogQL)
Chyby:
{job="syslog"} |= "error"
Počty chyb za minutu:
sum by (job) (rate(({job="syslog"} |= "error")[5m]))
Top služby s warn/error:
topk(5, sum by (job) (rate(({job="varlogs"} |~ "warn|error")[10m])))

8) Alerty (Grafana/Prometheus styl)
Internet down (ICMP neprojde 2 min):
avg_over_time(probe_success[2m]) < 1
Vysoká latence (p95 > 80 ms po 10 min):
histogram_quantile(0.95, sum(rate(probe_icmp_duration_seconds_bucket[10m])) by (le, instance)) > 0.08
Zaplněný disk (node_exporter):
(node_filesystem_avail_bytes{fstype!~"tmpfs|overlay"} / node_filesystem_size_bytes) < 0.1
Port zahlcený > 80 % po 15 min:
( rate(ifHCOutOctets[5m]) * 8 ) / 1e9 * 100 > 80
V Grafaně nastav contact points (e-mail/Telegram/Slack), alert rules a notification policies.

9) Síťové speciality pro domácnost
    • OpenWrt: SNMP nebo prometheus-node-exporter-lua + collectd/prometheus moduly.
    • MikroTik: SNMP (LTE/PPP, interface counters), případně /tool graphing + export; existují i community exportery.
    • UniFi: buď SNMP, nebo metriky přes UNMS/Controller (existují community exportery).
    • Pi-hole/AdGuard: grafy DNS dotazů (exporter existuje).
    • NAS (Synology/QNAP): SNMP + logy; některé mají oficiální/prom komunitní exportery.
    • UPS: apcupsd_exporter.
    • Speedtest: spouštěj periodicky (např. cron + prometheus-pushgateway nebo dedikovaný speedtest exporter) → graf rychlosti a jitteru.
    • NetFlow/sFlow/IPFIX: pro hlubší pohled na to, kdo žere šířku pásma, nasadíš např. ntopng (mimo Grafanu), ale jde integrovat přes pluginy/datasource.

10) Bezpečnost & provoz
    • Oddělená VLAN pro monitorovací stack (nepovinné, ale pěkné).
    • Reverse proxy (Caddy/Traefik/Nginx) + TLS pro Grafanu.
    • Zálohy: volume Grafany, Promethea a Loki.
    • Role-Based Access (RBAC) v Grafaně (Org roles, Folder permissions).
    • Aktualizace kontejnerů (watchtower/ručně) a verzí dashboardů.
    • Retence: Prometheus --storage.tsdb.retention.time=30d (podle disku). Pro delší historii zvaž VictoriaMetrics/Thanos.
    • Resource limity (Docker deploy.resources) na slabém HW.

11) Výkon a škálování doma
    • Prometheus: scrape_interval 15s–60s; více cílů → delší interval.
    • SNMP: opatrně s častým pollingem na slabých routerech (30–60s je bezpečné).
    • Loki: logy filtruj (Promtail pipelines) – sniž šum.
    • U třetích zařízení preferuj push do syslogu → promtail čte a posílá do Loki.

12) Pokročilosti (masterclass)
a) Dashboard design
    • Proměnné: instance, device, interface (SNMP ifName).
    • „Repeating panels“ podle rozhraní.
    • Transformace: join/merge time series, math (přepočet na % kapacity).
    • Anotace: události (restart routeru, změna ISP modemu).
b) SLO / SLI pro domácí síť
    • SLI dostupnosti internetu: probe_success (95–99.9 %).
    • Latence p95 < 50–80 ms k DNS.
    • Chybovost rozhraní ~0; alert na increase(ifInErrors[15m]) > 0.
c) Synthetic monitoring
    • Blackbox na důležité domény (DNS, banky, práce, Git, streaming).
    • TCP port checks (NAS, SSH, MQTT, Home Assistant).
d) Logy – enrichment
    • Promtail pipeliny: přidávej labels (host, app), drop šum (healthchecky), parse JSON logy.
e) Provisioning-as-Code
    • V Grafaně ulož datasources/dashboards/alert rules do YAML → repo (Git), snadná obnova.
f) Remote_write & dlouhá historie
    • Prometheus → VictoriaMetrics (jednoduchý, úsporný) pro delší retention.
    • Pro více lokací (např. chata) uvaž federaci nebo remote_write.
g) eBPF / L3–L7 přehled
    • Na Linux gateway můžeš použít Cilium/Hubble (pokročilé), ale to už je nad rámec běžného domu. Díky eBPF uvidíš flow, latence, policy drops.
h) Tracing (Tempo)
    • Pokud máš domácí služby (Docker stacky) a chceš traces (OpenTelemetry), přidej Tempo a zobraz v Grafaně. Praktické pro debug HA/MQTT, ale spíš bonus.

13) Check-list: co přesně udělat, krok za krokem
    1. Vyber stroj (Raspberry Pi 4 / mini-PC) + Docker.
    2. Vytvoř adresáře a soubory dle bodu 3.
    3. docker compose up -d.
    4. Přihlas se do Grafany → přidej datasources Prometheus + Loki.
    5. Importuj/vytvoř dashboard:
        ◦ „Internet health“ (Blackbox ICMP/HTTP).
        ◦ „Router/Switch interfaces“ (SNMP if_mib).
        ◦ „Host overview“ (node_exporter).
    6. Zapni alerty (e-mail/Telegram): internet down, vysoká latence, zaplněný disk, chybující porty.
    7. Přidej další exportery: UPS, speedtest, smartctl, Pi-hole.
    8. Vyladění retence a bezpečnosti (TLS, hesla, zálohy).
    9. Přidej proměnné a repeating panely.
    10. Zaveď provisioning (datasources/dashboards do YAML, Git).

14) Typické problémy & řešení
    • SNMP nic nevrací: povol SNMP v zařízení, ověř komunitu/IP whitelist; zkus snmpwalk.
    • Blackbox „probe_failed“: firewall/ICMP blok; testni z kontejneru docker exec -it blackbox_exporter ping 1.1.1.1.
    • Prometheus nevidí target: špatná adresa/port; podívej se na Status → Targets.
    • Loki nic neukládá: zkontroluj cesty promtailu (__path__), práva na logy, a clients.url.
    • Grafana panely „No data“: zkontroluj časové okno a labels (např. instance vs ip:port).

15) Rozšíření pro tvoje prostředí
    • Arch Linux / NAS Synology:
        ◦ Arch: balíky prometheus-node-exporter, promtail, nebo docker.
        ◦ Synology: SNMP zapnout v Ovládacím panelu; logy přes syslog → promtail.
    • Home Assistant: integrace metrik do Promethea (plugin/integrace) a logy do Loki.
    • DNS resolver (Unbound/Pi-hole/AdGuard): exportery existují; sleduj dotazy/odpovědi, blokování, latence.

16) Co budeš po tomhle umět (cíle masterclass)
    • Osadit celý monitoring stack během pár minut.
    • Číst a psát PromQL/LogQL dotazy pro praktické sítě.
    • Navrhovat SLI/SLO a alerty, které nešumí.
    • Diagnostikovat problémy (latence, packet loss, zahlcené porty, chybové logy).
    • Udržovat stack bezpečně, úsporně a automatizovaně.

Jasně — jen stručné „kam co dát“ a „co přesně napsat“. Neopakuju celou teorii, jen praktické kroky.
Kam nahrát soubory (struktura)
Zvol si složku, např. ~/homelab-monitoring/ a uvnitř udělej přesně tohle:
homelab-monitoring/
├─ docker-compose.yml
├─ grafana/                # vytvoří se sama po startu (data Grafany)
├─ prometheus-data/        # vytvoří se sama po startu (data Promethea)
├─ prometheus/
│  └─ prometheus.yml
├─ blackbox/
│  └─ blackbox.yml
├─ snmp/
│  └─ snmp.yml
├─ loki/                   # vytvoří se sama po startu (data Loki)
├─ loki-config.yaml
└─ promtail-config.yaml
Jak to udělat – úplně jednoduše (krok za krokem)
    1. Připrav složku
mkdir -p ~/homelab-monitoring/{prometheus,blackbox,snmp}
cd ~/homelab-monitoring
    2. Vytvoř soubory (otevři editor a vlož obsah, co jsem ti dal minule):
nano docker-compose.yml
nano prometheus/prometheus.yml
nano blackbox/blackbox.yml
nano snmp/snmp.yml
nano loki-config.yaml
nano promtail-config.yaml
Ulož vždy Ctrl+O, Enter, a ven Ctrl+X.
    3. Uprav IP adresy podle sebe
    • prometheus/prometheus.yml → v sekcích blackbox-icmp, blackbox-http a snmp nahraď příklady za tvoje IP/domény (gateway, DNS, NAS, router, switch).
    • snmp/snmp.yml → změň community: public na tvoji SNMP komunitu (a zapni SNMP na routeru/switchi).
    • blackbox/blackbox.yml obvykle není třeba měnit.
    4. Spusť to
docker compose up -d
    5. Zkontroluj, že kontejnery běží
docker ps
Měl bys vidět: grafana, prometheus, node_exporter, blackbox_exporter, snmp_exporter, loki, promtail.
    6. Otevři Grafanu
    • Prohlížeč → http://<IP_tvého_stroje>:3000
    • Přihlas: admin / change_me (hned si heslo změň).
    7. Přidej datové zdroje v Grafaně
    • Prometheus: URL http://prometheus:9090
    • Loki: URL http://loki:3100
Ulož „Save & test“ u obou.
    8. Mrkni v Prometheu na targets (diagnostika)
    • http://<IP>:9090 → Status → Targets
    • Vše by mělo být „UP“. Když něco padá:
        ◦ Blackbox → často firewall/ICMP blok.
        ◦ SNMP → špatná komunita/nezapnuté SNMP nebo špatná IP.
    9. Start/stop/update (jak s tím pracovat)
# start
docker compose up -d
# stop
docker compose down
# znovu načtení konfigurace Promethea (když upravíš prometheus.yml)
docker kill -s HUP prometheus
# update na nové verze image
docker compose pull && docker compose up -d
# logy konkrétní služby
docker logs -f prometheus
    10. Kde co upravovat do budoucna
    • Přidání/odebrání měřených IP/domén: prometheus/prometheus.yml
    • SNMP moduly/komunita: snmp/snmp.yml
    • Cesty k logům: promtail-config.yaml
    • Retence Promethea (délka historie): parametr v docker-compose.yml u prometheus (--storage.tsdb.retention.time=30d)
